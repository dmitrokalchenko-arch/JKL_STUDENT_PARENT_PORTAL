# Family Dashboard

## Статус согласования

**Черновик — ожидает визуального согласования.**

Соответствует экрану `FAMILY-001` в `docs/SCREEN_REGISTRY.md`.

## 1. Назначение

Главный экран после входа в семейный аккаунт. Показывает верхнюю панель
семьи, профиль и два круглых индикатора выбранного ребёнка, ряд
dashboard-кнопок и нижнюю динамическую область, в которой отображается
содержимое одного выбранного раздела (включая раздел «Моя семья» —
`FAMILY-002`, см. `prompts/family/my_family.md`).

## 2. Роль пользователя
- Family (семейный аккаунт — родитель/опекун и, при необходимости, ребёнок
  под общим входом, см. `docs/architecture/FAMILY_ACCOUNT_CONCEPT.md`)

Тренер использует отдельный вход и отдельную навигацию (`TRAINER-*`) — этот
экран не относится к тренеру.

## 3. Пользовательский сценарий

1. Семья входит по уникальному нику семьи (пароль — общий, см.
   `memory/BUSINESS_RULES.md`, правило 22).
2. Если привязан один ребёнок — его страница выбирается автоматически.
3. Если привязано несколько детей — семья видит переключатель (отдельная
   строка под верхней панелью) и выбирает ребёнка либо там, либо через
   раздел «Моя семья».
4. После входа автоматически открывается раздел «Мои тренировки»; активна
   только кнопка «Мои тренировки». Отдельного неименованного «обзора» не
   существует — дефолтное содержимое нижней динамической области **всегда**
   является содержимым одного из семи именованных разделов.
5. Нажатие любой dashboard-кнопки заменяет содержимое нижней динамической
   области; активная кнопка выделяется.
6. Переключение ребёнка в любой момент обновляет все блоки страницы,
   включая уже открытый раздел.

## 4. Доступные данные

- Все данные всех детей, привязанных к семейному аккаунту через
  `family_students` (см. `docs/database/FAMILY_ACCOUNT_DATA_MODEL_DRAFT.md`).
- Профиль, тренировки, достижения, сертификаты, мероприятия, техники,
  договор и оплата выбранного ребёнка.
- Уведомления, относящиеся к семейному аккаунту.

## 5. Запрещенные данные

- Данные детей, не привязанных к этому семейному аккаунту.
- Банковские реквизиты и платёжные токены — эти поля не показываются даже
  семье в виде полного набора необработанных данных платёжного провайдера
  (безопасное описание способа оплаты — да, сырые данные карты — нет; см.
  `docs/database/FAMILY_ACCOUNT_DATA_MODEL_DRAFT.md`, «Что не нужно
  хранить»).
- Данные SaaS-биллинга клуба перед платформой JCL (`clubs.contract_*`,
  `club_payments`) — не относятся к семейному кабинету вообще.

## 6. Структура интерфейса

### Верхняя панель

- логотип JKL Club;
- название семейного аккаунта (`display_name`);
- приветствие (например, «Добро пожаловать, семья Мюллер») — **утверждено:**
  постоянный элемент верхней панели;
- кнопка выхода;
- кнопка настроек семейного аккаунта;
- кнопка/индикатор уведомлений.

Переключатель ребёнка **не является частью верхней панели** — см. отдельный
раздел ниже.

### Переключатель ребёнка

Располагается отдельной горизонтальной строкой **под** верхней панелью, не
внутри неё.

- Если ребёнок один — переключатель отображается компактно (например,
  просто имя выбранного ребёнка, без карточек выбора).
- Если детей несколько — становится полноценной горизонтальной панелью
  выбора: карточка с фотографией, именем и текущим поясом каждого ребёнка,
  активный ребёнок визуально выделен.

### Основной профиль выбранного ребёнка

- фотография;
- имя и фамилия;
- дата рождения или возраст;
- группа;
- вид спорта;
- текущий пояс;
- следующий пояс.

### Два круглых индикатора

1. **Возраст допуска к следующему экзамену** — показывает, достигнут ли
   минимальный возраст, и если нет — сколько времени осталось.
2. **Рейтинговые баллы** — текущие баллы, требуемые баллы (если есть
   норматив), визуальный прогресс.

### Dashboard-кнопки

1. Моя семья
2. Мои тренировки
3. Мои достижения
4. Мои сертификаты
5. Мои мероприятия
6. Необходимые техники
7. Договор и оплата

Кнопка «Мои курсы» не создаётся.

### Нижняя динамическая область

- отображает содержимое только одного выбранного раздела;
- по умолчанию после входа открыт раздел «Мои тренировки» — активна именно
  кнопка «Мои тренировки»; отдельного неименованного «обзора» не существует;
- при нажатии dashboard-кнопки содержимое заменяется, остальные разделы не
  показываются одновременно;
- активная кнопка визуально выделена;
- переключение ребёнка обновляет всю информацию в этой области, не меняя
  при этом, какой именно раздел открыт.

## 7. Кнопки и действия

- Выход из аккаунта.
- Открытие настроек семейного аккаунта.
- Просмотр уведомлений.
- Переключение выбранного ребёнка.
- Переход по каждой из 7 dashboard-кнопок.

## 8. Состояния

- **Загрузка** — данные семьи/ребёнка ещё запрашиваются.
- **Семейный аккаунт без привязанных детей** — показать пояснение и
  действие «Запросить добавление ребёнка» (ведёт в «Моя семья»,
  `FAMILY-012`).
- **Один ребёнок** — автоматический выбор, переключатель компактный.
- **Несколько детей** — заметный переключатель, выбор обязателен при первом
  входе (или сохраняется выбор с прошлой сессии).
- **Нет данных в выбранном разделе** — например, у ребёнка пока нет
  достижений/сертификатов — понятное пустое состояние с пояснением.
- **Ошибка загрузки** — сообщение об ошибке с возможностью повторить
  попытку.
- **Договор отсутствует** — раздел «Договор и оплата» показывает, что
  договор пока не оформлен клубом, вместо пустой таблицы.
- **Платёжные данные ещё не заведены** — аналогично, отдельное пояснение.
- **Запрос на привязку ребёнка ожидает подтверждения** — ребёнок из запроса
  не отображается как полноценно привязанный; в «Моей семье» видно, что
  запрос в статусе «ожидает» (см. `prompts/family/my_family.md`, раздел D).
- **Аккаунт временно заблокирован** — вместо dashboard показывается
  сообщение о блокировке без доступа к данным детей.

## 9. Адаптивность

Основной формат — desktop landscape:
- без бокового меню;
- тёмный стиль JKL Club, золотые акценты (см. `memory/UI_RULES.md`);
- адаптация для планшета и телефона предусматривается отдельно, на этом
  этапе не проектируется подробно.

## 10. Бизнес-правила

См. `memory/BUSINESS_RULES.md`, правила 1–30, в первую очередь:
- правило 3–5 — выбор активного ребёнка и обновление всех блоков;
- правило 22–23 — вход по нику, смена пароля семьёй;
- правило 26–27 — договор привязан к ребёнку, разные условия у разных
  детей.

## 11. Необходимые общие компоненты

- Карточка ребёнка (переиспользуется и в «Моей семье», см.
  `prompts/family/my_family.md`, раздел A).
- Круглый индикатор (для возраста допуска и рейтинга).
- Dashboard-кнопка.
- Компонент нижней динамической области с переключением содержимого.

- Все перечисленные состояния (раздел 8) учтены в макете.
- Переключение ребёнка и dashboard-кнопок описано однозначно.
- Не содержит запрещённых данных (раздел 5).
