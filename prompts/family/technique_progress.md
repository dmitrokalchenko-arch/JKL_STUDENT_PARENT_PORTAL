# Прогресс техник (Technique Progress)

## 1. Назначение

Самостоятельный блок главной страницы Family Dashboard. Показывает прогресс
выбранного ребёнка по техникам текущего пояса: сколько техник уже выполнено,
сколько осталось (раздельно Tachi-waza / Ne-waza), и прогресс к бонусу за
количество выполненных техник. Не является вкладкой и не относится к
`ContentArea` — отображается всегда (если включён), независимо от того,
какая dashboard-кнопка выбрана снизу.

## 2. Роль пользователя
- Shared (Family) — блок виден семье в рамках единого семейного аккаунта, как
  и три карточки профиля над ним. Отдельного разделения Student/Parent нет
  (см. `memory/BUSINESS_RULES.md`).

## 3. Пользовательский сценарий

1. Семья открывает Family Dashboard, выбран один ребёнок (или переключает
   ребёнка через `ChildSelector`).
2. Между тремя карточками профиля и dashboard-кнопками виден блок «Прогресс
   техник» с данными именно выбранного ребёнка.
3. Пользователь видит крупные карточки уже выполненных техник и пустые слоты
   до бонуса, затем два компактных списка техник, которые ещё предстоит
   выполнить (Tachi-waza, Ne-waza).
4. Клик по выполненной технике открывает по центру экрана модальное окно с
   видео техники (или заглушку «видео пока не добавлено», если файла нет).
   Клик по невыполненной технике никакого действия не производит.
5. Модалка закрывается кнопкой закрытия, клавишей Esc или кликом по оверлею.

## 4. Доступные данные

- Прогресс техник выбранного в данный момент ребёнка (`techniqueProgress[selectedChild.id]`).
- Для каждой техники: id, название, категория (`tachi-waza` / `ne-waza`),
  статус (`completed` / `required`), изображение (опционально), ссылка на
  видео (опционально, только для выполненных).
- `bonusRequirement` — сколько техник нужно выполнить для бонуса (задаётся
  тренером в будущем, сейчас — мок).

## 5. Запрещённые данные

- Данные других детей семьи, не являющихся выбранными в данный момент.
- Редактирование статуса техники (недоступно на этом этапе — только чтение).
- Загрузка/изменение видео (не входит в этап 1).

## 6. Структура интерфейса

Блок из трёх строк:

1. **Выполненные техники** — крупные карточки (изображение, название,
   зелёная галочка), затем пустые слоты. Количество пустых слотов =
   `max(bonusRequirement - completedCount, 0)`. Карточки кликабельны →
   открывают `TechniqueVideoModal`.
2. **Tachi-waza** — компактные карточки техник со статусом `required` и
   категорией `tachi-waza`. Без галочек, без статусов, некликабельны.
3. **Ne-waza** — компактные карточки техник со статусом `required` и
   категорией `ne-waza`. Без галочек, без статусов, некликабельны.

Техника существует только в одном месте одновременно — единый массив
`techniques` с полем `status`, группы формируются селектором
`selectTechniqueGroups()`, дублирование архитектурно исключено.

## 7. Кнопки и действия

- Клик по выполненной технике → открыть `TechniqueVideoModal`.
- В модалке: Play/Pause/перемотка/звук/fullscreen (нативные контролы
  `<video>`), закрытие по кнопке/Esc/клику по оверлею.
- Невыполненные техники и пустые слоты — не интерактивны.

## 8. Состояния

- **featureEnabled = false (на любом уровне) → блок полностью не рендерится**
  (см. п. 10 «Бизнес-правила» — двойной flag).
- **Загрузка** — не реализуется на этом этапе (данные из мока синхронны);
  архитектурно точка расширения — `TechniqueProgressSection` получает данные
  через props, поэтому в будущем легко подставить `loading`-состояние без
  переделки структуры.
- **Нет данных** — выполненных техник нет: первая строка целиком состоит из
  пустых слотов (`bonusRequirement` штук).
- **Успех** — обычное состояние, смесь заполненных карточек и слотов.
- **Видео недоступно** — у выполненной техники нет `videoUrl`: модалка
  открывается, но вместо `<video>` показывает нейтральную заглушку «Видео
  пока не добавлено». Внешние тестовые URL не используются намеренно, чтобы
  модуль не зависел от стороннего сервера.
- **Ограниченный доступ** — не применимо на этом этапе (нет тренера/админки).

## 9. Адаптивность

- **Desktop (альбомный экран):** карточки в ряд слева направо в каждой из
  трёх строк; при переполнении — горизонтальная прокрутка (как у
  `ChildSelector`), без переноса на новую строку.
- **Mobile:** те же три строки, карточки меньше, каждая строка — отдельная
  горизонтально прокручиваемая область (свайп).

## 10. Бизнес-правила

- Видимость блока — **двойной feature flag**:

  ```js
  const isVisible =
    featureFlags.techniqueProgress &&   // глобальный технический флаг (мок)
    progressData?.featureEnabled;       // задел под клубную/дочернюю настройку
  ```

  Глобальный флаг — техническое отключение всего модуля на уровне сборки.
  `featureEnabled` в данных — задел под будущую настройку конкретного клуба
  или ребёнка. Оба должны быть `true`, иначе блок не рендерится вообще (ни
  DOM, ни попытки чтения данных техник).
- Данные привязаны к выбранному ребёнку — переключение ребёнка обновляет
  весь блок (аналогично правилу 5 из `memory/BUSINESS_RULES.md`).
- Единый источник правды — техника не может одновременно находиться в списке
  выполненных и в списке необходимых.
- При первом открытии Family Dashboard ни одна нижняя dashboard-кнопка не
  активна, `ContentArea` ничего не отображает (переопределяет прежнее
  решение — см. `memory/UI_RULES.md`). Блок «Прогресс техник» на это не
  влияет и виден независимо от состояния нижних вкладок.

## 11. Необходимые общие компоненты

- `src/components/common/Modal.jsx` — новый универсальный компонент
  центрального модального окна (переиспользуем за пределами этого блока).
- `Icon.jsx` — для галочки и вспомогательных иконок.

## 12. Зависимости

- `useSelectedChild` (существующий хук) — определяет, чьи данные показывать.
- Мок-данные: `src/mocks/techniqueProgressMock.js`.
- Селектор: `src/utils/techniqueProgress.js`.
- Feature flag: `src/config/featureFlags.js`.

## 13. Критерии готовности

- Блок отображается между тремя карточками профиля и dashboard-кнопками, вне
  `ContentArea`.
- Переключение ребёнка меняет данные блока.
- `featureFlags.techniqueProgress = false` или `progressData.featureEnabled = false`
  полностью скрывает блок.
- Выполненные техники не встречаются в списках Tachi-waza/Ne-waza.
- Количество пустых слотов = `bonusRequirement - completedCount` (не меньше 0).
- Модалка открывается по клику на выполненную технику, закрывается тремя
  способами (кнопка, Esc, оверлей), не даёт фону прокручиваться, пока
  открыта.
- При первом входе ни одна dashboard-кнопка не активна.
- Нет ошибок/предупреждений в консоли браузера.
- Проверено на desktop (альбомная ориентация) и мобильном экране.
- Компоненты принимают данные через props, не импортируют мок напрямую
  (кроме сервисного слоя `techniqueProgressService.js`, где mock — явный
  dev-fallback при отсутствии Supabase, см. этап 2 ниже).
- Компонент показывает состояния loading/error/empty («программа пояса не
  настроена») сверх исходных требований этапа 1 — добавлено на этапе 2 без
  изменения расположения блока, размеров карточек и логики модального окна.

## 14. Что не входит в текущую задачу

Роадмап последующих этапов (порядок фиксированный, не начинать без отдельного
подтверждения пользователя):

- **Этап 1:** UI блока «Прогресс техник» и mock-данные. Готово.
- **Этап 2:** модель данных, сервисный слой, Supabase (включая family-слой
  Auth — оказался предпосылкой), RLS, Storage. SQL написан
  (`docs/database/FAMILY_AUTH_AND_TECHNIQUE_PROGRESS_SCHEMA.md`), **не
  применён к реальной базе** — ждёт проверки пользователем.
- **Этап 3:** интерфейс тренера (просмотр и редактирование статуса техник
  учеников) — включая решение по тренерской аутентификации (сейчас PIN, не
  Supabase Auth).
- **Этап 4:** административные настройки клуба (управление списком техник,
  `bonusRequirement`, клубной `featureEnabled`-настройкой).

На этапе 2 не созданы: страница тренера, административная панель, UI
загрузки видео/изображений, редактирование техник в интерфейсе, визуальный
дизайн экрана входа семьи (сделана только функциональная версия).
