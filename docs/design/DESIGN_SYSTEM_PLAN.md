# Design System Plan — JKL Club

Это план будущей единой системы дизайна. Документ не содержит кода
компонентов и не фиксирует окончательные значения — только структуру
для последующего согласования с пользователем.

## A. Цвета

| Назначение | Описание | Значение |
|---|---|---|
| Основной темный фон | Фон страницы | требует утверждения |
| Фон карточек | Фон блоков/карточек поверх основного фона | требует утверждения |
| Золотой основной акцент | Ключевые акценты, активные элементы | требует утверждения |
| Светло-золотой акцент | Второстепенные акценты, hover-состояния | требует утверждения |
| Основной текст | Светлый текст на тёмном фоне | требует утверждения |
| Вторичный текст | Приглушённый текст, подписи | требует утверждения |
| Успешное состояние | Успех, подтверждение действия | требует утверждения |
| Предупреждение | Предупреждающие сообщения | требует утверждения |
| Ошибка | Ошибки, критичные состояния | требует утверждения |
| Неактивное состояние | Disabled-элементы | требует утверждения |

## B. Типографика

| Назначение | Описание |
|---|---|
| Заголовок страницы | Название экрана (например, "Мои тренировки") |
| Заголовок блока | Название раздела внутри страницы |
| Основной текст | Обычный текст интерфейса |
| Вспомогательный текст | Подписи, пояснения, метаданные |
| Числа и показатели | Рейтинговые баллы, возраст допуска, счётчики |
| Подписи кнопок | Текст на кнопках и dashboard-плитках |

Гарнитура, размеры и начертания — требуют отдельного утверждения.

## C. Компоненты

Планируемый список переиспользуемых компонентов (без реализации):

- основная кнопка;
- вторичная кнопка;
- dashboard-кнопка;
- карточка;
- модальное окно;
- вкладки;
- поле ввода;
- выпадающий список;
- таблица;
- уведомление;
- пустое состояние;
- skeleton/loading;
- progress bar;
- круговой индикатор;
- badge статуса;
- изображение профиля;
- элемент мероприятия;
- элемент тренировки;
- элемент достижения;
- карточка сертификата.

## D. Состояния компонентов

Каждый интерактивный компонент должен предусматривать состояния:

- default;
- hover;
- active;
- focus;
- disabled;
- loading;
- success;
- warning;
- error.

## E. Адаптивность

- desktop landscape — основной формат;
- tablet;
- mobile;
- минимальная ширина;
- перенос dashboard-кнопок (поведение при сужении экрана);
- изменение размеров карточек;
- поведение модальных окон на разных экранах.

## F. Доступность

- достаточный контраст текста и фона;
- клавиатурная навигация по всем интерактивным элементам;
- видимый focus-индикатор;
- понятные текстовые подписи для всех элементов управления;
- иконка не должна быть единственным источником смысла (обязательно
  текстовое сопровождение или aria-подпись).

## Статус документа

Черновик плана. Ни один визуальный параметр не является окончательным
до отдельного согласования с пользователем. Реализация компонентов не
начинается до утверждения этого плана.
