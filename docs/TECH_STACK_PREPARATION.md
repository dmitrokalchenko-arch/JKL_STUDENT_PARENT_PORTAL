# Подготовка к выбору технического стека

Этот документ — не выбор технологий, а список вопросов, которые нужно
будет определить **после утверждения дизайна** (статус Design Approved).

## Текущий статус

На момент создания этого документа статус дизайна — **Requires Minor
Fixes** (см. `docs/design/FAMILY_DASHBOARD_V2_REVIEW_RESULT.md`), не
Design Approved. Выбор технического стека **ещё не начинается** — этот
документ подготовлен заранее, чтобы вопросы были готовы к обсуждению сразу
после утверждения макета.

## Что необходимо определить после утверждения дизайна

- **Frontend** — на чём будет реализован интерфейс.
- **Backend** — нужен ли отдельный backend или вся логика через Supabase.
- **Авторизация** — как технически реализовать вход по семейному нику,
  общий пароль на семью, отдельный вход тренера (см. открытые технические
  вопросы в `docs/architecture/FAMILY_ACCOUNT_CONCEPT.md`, раздел 15).
- **Структура проекта** — организация папок, разделение по ролям
  (семья/тренер), общие компоненты.
- **Supabase** — использовать ли существующий проект `JCL_Gruppen` напрямую
  или отдельную схему/проект; как организовать RLS-политики (см.
  `memory/BUSINESS_RULES.md`, правило 19; `docs/database/FAMILY_ACCOUNT_DATA_MODEL_DRAFT.md`).
- **Маршрутизация** — как организовать переходы между Family Dashboard,
  «Моя семья», «Договор и оплата» и остальными разделами.
- **Компоненты** — какие общие переиспользуемые компоненты нужны (карточка
  ребёнка, круглый индикатор, dashboard-кнопка и т.д. — см.
  `prompts/family/dashboard.md`, раздел 11).
- **Управление состоянием** — как хранить и обновлять выбранного ребёнка,
  открытый раздел, данные семьи.
- **Адаптивность** — как технически реализовать переход между desktop
  (4 блока в ряд), планшетом (сетка 2×2) и мобильным (вертикальный стек) —
  см. `memory/UI_RULES.md`.
- **Стратегия разработки** — порядок реализации экранов, приоритеты,
  подход к тестированию.

## Ограничение

Ни одна конкретная технология, фреймворк, библиотека или провайдер не
выбираются в этом документе — только список вопросов для последующего
обсуждения.
