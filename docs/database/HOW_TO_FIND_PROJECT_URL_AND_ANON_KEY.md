# Как найти Project URL и anon key (для будущего staging-подключения)

Понадобится позже, когда дойдём до настройки `.env` фронтенда
(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) для staging-окружения —
**не сейчас**, это просто справка на будущее. Присылать мне эти значения
пока не нужно.

## Где посмотреть

1. В [Supabase Dashboard](https://supabase.com/dashboard) откройте нужный
   проект.
2. В левом меню откройте **Project Settings** (иконка шестерёнки, обычно
   внизу меню).
3. Откройте раздел **API** (иногда называется **Data API** или
   **API Keys**, в зависимости от версии Dashboard).
4. На этой странице вы увидите:
   - **Project URL** — адрес вида `https://xxxxxxxxxxxx.supabase.co`. Это
     значение для `VITE_SUPABASE_URL`.
   - **Project API keys** — список из нескольких ключей. Нужен только тот,
     что подписан **`anon` / `public`** — это значение для
     `VITE_SUPABASE_ANON_KEY`. Он специально предназначен для
     использования в браузере/frontend-коде — его безопасность как раз и
     обеспечивают написанные RLS-политики (без них anon-ключ давал бы
     слишком широкий доступ, но с ними — только то, что разрешают policy).

## Что НЕ нужно делать

- **Не копируйте и не присылайте `service_role` key** (иногда подписан
  `service_role` / `secret`) — этот ключ полностью обходит все RLS-политики
  и даёт полный доступ к базе. Он предназначен только для серверного кода
  (в нашем случае — Edge Function `create-family-account`, куда попадает
  через `supabase secrets set`, отдельная процедура) и никогда не должен
  оказаться в `.env` фронтенда, в браузере или в переписке.
- Не вставляйте `anon key` в переменные с префиксом, отличным от `VITE_`, и
  не публикуйте его как секрет — он и задуман как публично видимый в
  собранном frontend-коде (это нормально для Supabase, безопасность
  обеспечивает RLS, а не секретность этого ключа).

## Дальше

Когда мы дойдём до реальной настройки staging-окружения, я отдельно
попрошу подтвердить, что `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`
записаны в `.env` (не в `.env.example`, который остаётся пустым шаблоном) —
это будет отдельный, явно согласованный шаг, не раньше, чем миграции будут
адаптированы под реальные типы и проверены локально.
