# Локализация (i18n) — реализация

Статус: **реализовано и протестировано** (frontend-прототип, без бэкенда).
Стек: React + Vite + JavaScript + CSS Modules, `i18next` + `react-i18next` +
`i18next-browser-languagedetector`.

### Региональные варианты де (`de-DE` / `de-AT` / `de-CH`)

Архитектура уже подготовлена для добавления региональных вариантов:
`normalizeLanguageCode()` в `src/i18n/languages.js` сводит любой региональный
код (`de-AT`, `de-CH`, `en-US`, `ar-SA` и т.д.) к базовому поддерживаемому
коду через `REGION_OVERRIDES` (сейчас пустой) → общий алгоритм "взять первый
subtag". Чтобы добавить отдельную ветку **de-AT** в будущем:

1. Создать `src/i18n/locales/de-AT/translation.json` (полная копия `de` с
   нужными региональными правками).
2. Добавить в `SUPPORTED_LANGUAGES` новую запись `{ code: 'de-AT', locale:
   'de-AT', ... }` и в `SUPPORTED_CODES`.
3. Добавить `REGION_OVERRIDES['de-at'] = 'de-AT'`, чтобы `de-AT` не сводился
   к обычному `de`.
4. Обновить `loadLanguage()` — логика подключения не меняется, так как она
   уже работает по `normalized`-коду.

Никаких других изменений архитектуры не требуется.

## 2. Установленные пакеты

Единственные добавленные зависимости (`package.json`):

- `i18next`
- `react-i18next`
- `i18next-browser-languagedetector`

Никакой дополнительный backend-loader (`i18next-http-backend` и т.п.) не
подключался — динамическая подгрузка реализована вручную через `import()`.

## 3. Динамическая загрузка переводов

`src/i18n/index.js`:

- При старте статически импортируется **только** `de/translation.json`
  (используется как ресурс по умолчанию и как fallback).
- `loadLanguage(code)` динамически подгружает `./locales/{code}/translation.json`
  через `import()` — Vite автоматически разбивает каждый файл на отдельный
  chunk (см. раздел «Размер сборки» ниже).
- Загруженные бандлы регистрируются через `i18n.addResourceBundle(...)` и
  кешируются в `loadedLanguages` (Set), чтобы не грузить повторно.
- При старте приложения (`ensureInitialLanguageLoaded()`, вызывается в
  `src/main.jsx` **до** рендера) догружается только язык, определённый
  детектором — остальные 10 языков не загружаются, пока пользователь не
  выберет их вручную.

### Исправленная ошибка определения языка при первой загрузке

Изначально `ensureInitialLanguageLoaded()` вычислял язык как
`i18n.resolvedLanguage || i18n.language`. Баг: `i18n.resolvedLanguage` —
это язык, для которого **реально загружены ресурсы** (до динамической
подгрузки это всегда `de`, т.к. это единственный статический ресурс) — то
есть выражение всегда получало `'de'` и никогда не доходило до фактически
определённого языка браузера. Исправлено на `normalizeLanguageCode(i18n.language)`
— `i18n.language` содержит именно то, что определил `LanguageDetector`
(localStorage → `navigator.language` → `de`), независимо от того, загружены
ли для него ресурсы. Проверено: при `navigator.language = 'ru'` и пустом
`localStorage` приложение теперь при первом заходе действительно
догружает и показывает русский перевод (а не немецкий).

## 4. Порядок определения языка и персистентность

`detection.order = ['localStorage', 'navigator']`, fallback — `de`.

- Ключ в `localStorage`: **`jkl_family_language`**.
- Выбор языка через `LanguageSwitcher` вызывает `changeLanguage()`, который
  сам сохраняет код в `localStorage` (штатное поведение
  `i18next-browser-languagedetector` с `caches: ['localStorage']`).
- Проверено вручную: после `localStorage.clear()` + reload — язык
  определяется по `navigator.language`; после ручного переключения — язык
  сохраняется и восстанавливается после `location.reload()`.

## 5. LanguageSwitcher

`src/components/common/LanguageSwitcher/` (`.jsx` + `.module.css`).

- Компактный триггер (`shortLabel` + шеврон, например «DE ▾»), расположен в
  `FamilyHeader` рядом с иконками уведомлений/настроек.
- Выпадающее меню: `role="listbox"` / `role="option"`, код + родное название
  + маркер текущего языка.
- Полная доступность с клавиатуры: `ArrowUp`/`ArrowDown` — навигация,
  `Enter`/`Space` — выбор, `Escape` — закрытие, `Tab` — закрытие при потере
  фокуса; `aria-haspopup`, `aria-expanded`, `aria-label` на триггере,
  `aria-selected` на опциях.
- Закрывается по клику вне компонента.

## 6. RTL (арабский)

- При выборе `ar` `document.documentElement.lang = 'ar'` и
  `document.documentElement.dir = 'rtl'` выставляются автоматически
  (`applyDocumentDirection()`, подписано на событие `i18n.on('languageChanged', ...)`).
- `src/styles/global.css`: `html[dir='rtl'] body { direction: rtl; }`.
- Логотип, фото, круговые индикаторы (возраст/рейтинг) и числа **намеренно
  не зеркалятся** — для них используется утилитарный класс `.ltr-isolate`
  (`direction: ltr; unicode-bidi: isolate;`). Важно: класс **не** задаёт
  `display`, так как более ранняя версия с `display: inline-block` ломала
  флекс-раскладку `FamilyHeader` — при добавлении `.ltr-isolate` к новым
  элементам не добавляйте туда `display`.
- Расположение меню `LanguageSwitcher` корректируется под RTL через
  `:global([dir='rtl']) .menu { right: auto; left: 0; }` в
  `LanguageSwitcher.module.css`.
- В `FamilySection.module.css` `text-align: left` заменён на логическое
  `text-align: start` — корректно разворачивается в RTL.
- **Известные ограничения RTL** (сознательно не доводились до идеала, по
  прямому указанию — не гнаться за «идеальным» RTL-редизайном):
  - Раскладка не проходила ревью профессионального арабского
    UI/UX-специалиста — только техническая проверка (`dir`/`lang`,
    отсутствие зеркалирования запрещённых элементов, читаемость).
  - Таблица истории платежей и карточки тренировок используют общую
    flex/grid-раскладку с `text-align: start` — не переработаны отдельно
    под специфичные RTL-паттерны (например, зеркалирование стрелок
    пагинации, если такие появятся в будущем).

## 7. Структура ключей перевода

Пространства имён (namespace) в каждом `translation.json`:

```
common.*        — общие элементы (показать все, скоро, вкл/выкл, годы)
header.*         — верхняя панель, приветствие, уведомления
language.*       — подписи самого переключателя языка
childSelector.*  — переключатель ребёнка
student.*        — текущий/следующий пояс
exam.*           — индикатор возраста допуска к экзамену
rating.*         — индикатор рейтинговых баллов
dashboard.*      — 7 подписей dashboard-кнопок
trainings.*      — раздел «Мои тренировки»
family.*         — раздел «Моя семья»
contract.*       — раздел «Договор и оплата» (данные договора)
payments.*       — раздел «Договор и оплата» (платежи, способ оплаты)
statuses.*        — статусы (активен/оплачено/записан/тип продления и т.д.)
belts.*           — названия поясов
sports.*          — виды спорta (judo/karate) — **зарезервировано**, ни один
                     компонент пока не отображает вид спорта
groups.*          — названия учебных групп
roles.*           — роли членов семьи (родитель/опекун) — **зарезервировано**,
                     пока нигде не отображается
placeholders.*    — заглушка «раздел ещё не спроектирован»
errors.*          — сообщения об ошибках/пустых состояниях
```

Всего **93 семантических ключа** (без учёта форм множественного числа) на
язык, что даёт 103–143 «сырых» ключа в JSON в зависимости от количества
форм плюрализации языка (см. `docs/I18N_TRANSLATION_REVIEW.md`).

Ключи никогда не совпадают с самим переводимым текстом; переводы мок-данных
(пояса/группы/статусы) вынесены в `*Key`-поля (`beltKey: 'belts.yellow'`,
`groupKey: 'groups.children8to12'`, `statusKey: 'statuses.active'` и т.д.) —
сами мок-файлы (`src/mocks/*.js`) не содержат захардкоженного текста ни на
одном языке.

## 8. Плюрализация

Используется **встроенный механизм i18next** (`key_one`, `key_few`,
`key_many`, `key_other`, для арабского дополнительно `key_zero`/`key_two`),
основанный на `Intl.PluralRules` — никакой ручной суффиксной логики не
написано.

Формы по языкам (согласно CLDR):

- de, en, fr, tr, it, es, nl — `_one` / `_other`.
- ru, uk, pl — `_one` / `_few` / `_many` / `_other`.
- ro — `_one` / `_few` / `_other`.
- ar — `_zero` / `_one` / `_two` / `_few` / `_many` / `_other`.

Проверено вручную числами `0, 1, 2, 5, 11, 21, 22` для `common.years` на
ru/pl/ar/uk/ro — все формы грамматически верны (например, ru: «21 год» /
«22 года» / «11 лет»; pl: «21 lat» / «22 lata»; ro: «21 **de** ani» —
предлог «de» перед числами ≥20, отдельная форма `_other`, не `_few`; ar:
«سنة واحدة» (1, натуральная форма без цифры), «سنتان» (2, двойственное
число), «5 سنوات» (3–10, форма few), «11/21/22 سنة» (11–99, форма
many/other — единственное число после числительного, что грамматически
верно для арабского).

Ключи с числовым интерполированием (`{{count}}`): `common.years`,
`header.notificationsCount`, `exam.currentAge`, `exam.requiredAge`,
`exam.remainingYears`, `rating.pointsLabel`, `rating.remainingPoints`,
`family.childrenCount`, `trainings.count`, `payments.count`.

## 9. Форматирование дат/чисел/валют

`src/utils/formatters.js` — только `Intl.DateTimeFormat` / `Intl.NumberFormat`,
без ручной сборки строк:

- `formatDate(date, languageCode, options)`
- `formatDateRange(start, end, languageCode, options)` — использует
  `formatter.formatRange()`, если браузер поддерживает, иначе `"start – end"`.
- `formatCurrency(amount, languageCode, currency = 'EUR')`
- `formatNumber(value, languageCode, options)`
- `formatPercent(value0to100, languageCode, options)`

Локаль для `Intl` берётся из `languages.js` (`de → de-DE`, `ru → ru-RU` и
т.д.). Валюта пока фиксирована как **EUR** (мультивалютность не входила в
задачу). Проверено визуально: немецкий («31. August 2026», «€90,00 / Monat»),
турецкий («31 Ağustos 2026», «€90,00 / ay», «%72» — знак процента перед
числом, как принято в турецкой локали).

## 10. Компоненты, переведённые полностью

Все текстовые узлы вынесены в `t()` в: `FamilyHeader`, `LanguageSwitcher`,
`ChildSelector`, `StudentProfileCard`, `AgeIndicator`, `RatingIndicator`,
`DashboardButtons`, `TrainingsSection`, `FamilySection`, `ContractSection`,
`PlaceholderSection`, `ContentArea`, `FamilyDashboard` (страница).

Компоненты, не требовавшие изменений (принимают уже переведённые
строки/пропсы, не содержат собственного текста): `CircularIndicator`,
`DashboardButton`, `Icon`.

Не переводятся (согласно заданию) — технические значения и личные данные:
никнейм семьи (`mueller_family`), email, номер договора, последние 4 цифры
карты, **личные имена детей/тренеров** (например, «Леон Мюллер», «Томас
Бауэр» — в мок-данных хранятся как обычный текст на языке ввода, не как
переводческие ключи, и остаются неизменными при переключении языка — это
осознанное и ожидаемое поведение, а не пропущенный перевод).

- Сетка dashboard-кнопок: `display: grid; grid-template-columns:
  repeat(auto-fit, minmax(110px, 1fr));` (`DashboardButtons.module.css`).
- Подпись кнопки: `-webkit-line-clamp: 2` + `white-space: normal` +
  `overflow-wrap: break-word` — перенос максимум на 2 строки без
  принудительного многоточия (`DashboardButton.module.css`), плюс
  `min-height: 76px`, чтобы кнопки не «прыгали» по высоте.
- Проверено вручную (эмуляция узкой кнопки 70px): немецкое «Meine
  Veranstaltungen» корректно переносится на 2 строки, без переполнения и
  без обрезки текста ниже второй строки.
- На реальных ширинах (десктоп 1280px, мобильная 375px, тестовая ширина
  вплоть до ~158px на колонку) все 7 подписей на всех 12 языках умещаются
  в 1 строку — 2-строчный перенос является запасным поведением для более
  узких контейнеров, а не типичным состоянием.

## 12. Известные ограничения (честно, без приукрашивания)

- Пространства `sports.*` и `roles.*` зарезервированы, но не используются
  ни одним компонентом (мок-данные не отображают вид спорта и роль
  опекуна на текущих экранах) — переведены полностью на все 12 языков «про
  запас», без реального применения.
- Статус тренировки упрощён до булева `enrolled: true/false` вместо
  оригинальной русской грамматической формы «Записан/Записана/Записаться»
  (согласование по роду студента) — выбраны два состояния
  (`statuses.enrolled` / `statuses.register`) без родового согласования.
  Для будущей поддержки родового согласования потребуется отдельная схема
  ключей (например, `statuses.enrolled_m` / `statuses.enrolled_f`).
- Номер карты в разделе оплаты остаётся маскированным техническим значением
  (`•••• 1234`) — не переводится и не форматируется, что ожидаемо.
- Сборка Vite выдаёт информационное предупреждение о том, что
  `de/translation.json` одновременно статически и динамически
  импортируется в `src/i18n/index.js` (динамическая ветка нужна для общей
  функции `loadLanguage()`, но по факту никогда не выполняется для `de`,
  так как он уже в `loadedLanguages` с самого старта) — предупреждение не
  указывает на реальную дублирующую загрузку, `de` не выделяется в
  отдельный chunk и остаётся частью основного бандла.
- RTL-раскладка не проходила проверку носителем арабского языка — см.
  раздел 6.

## 13. Как добавить новый язык (после de-AT/de-CH)

1. Добавить запись в `SUPPORTED_LANGUAGES` (`src/i18n/languages.js`) с
   `code`, `locale`, `shortLabel`, `nativeName`, `direction`, `enabled: true`.
2. Создать `src/i18n/locales/{code}/translation.json` с полным набором из
   93 семантических ключей (используйте `de/translation.json` как эталон
   структуры) и нужными формами плюрализации для этого языка.
3. Ничего больше менять не нужно — `loadLanguage()`, `LanguageSwitcher` и
   `normalizeLanguageCode()` работают с новым языком автоматически, так как
   читают список из `SUPPORTED_LANGUAGES`.

Дополнительно проверено (все 12 языков через прямой вызов `changeLanguage()`
и вручную через `LanguageSwitcher` для нескольких языков):

- Переключение работает без ошибок в консоли браузера.
- Персистентность в `localStorage` (`jkl_family_language`) подтверждена
  после `location.reload()`.
- Оба ребёнка (Леон/Анна) корректно переключаются на всех проверенных
  языках, включая состояние «допуск не достигнут» (Анна).
- Разделы «Моя семья», «Договор и оплата» и заглушки («Мои достижения» и
  т.д.) открываются и полностью переведены.
- Ни разу не встретился «сырой» непереведённый ключ (`namespace.key`) или
  пустая строка на экране.
